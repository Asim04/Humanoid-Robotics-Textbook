## Code of Conduct

Please read and follow our [Code of Conduct](CODE_OF_CONDUCT.md) in all interactions within this project.

## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/your-username/physical-ai-humanoid-robotics.git`
3. Create a new branch: `git checkout -b feature/your-feature-name`
4. Make your changes
5. Test your changes locally
6. Commit your changes: `git commit -m 'Add some feature'`
7. Push to your fork: `git push origin feature/your-feature-name`
8. Submit a pull request

## Content Contributions

We welcome contributions to improve the textbook content, including:

- Correcting errors or typos
- Adding new examples or exercises
- Improving explanations
- Adding missing content
- Updating outdated information

### Content Structure

The textbook is organized as follows:
- `docs/part-i-foundations/` - Weeks 1-2 content
- `docs/part-ii-ros-fundamentals/` - Weeks 3-4 content
- `docs/part-iii-perception-control/` - Weeks 5-6 content
- `docs/part-iv-advanced-topics/` - Weeks 7-8 content
- `docs/part-v-integration-deployment/` - Weeks 9-10 content
- `docs/labs/` - Lab exercises
- `docs/code-examples/` - Code examples
- `docs/appendices/` - Reference materials

## Technical Contributions

We also welcome technical improvements, including:

- Bug fixes
- Performance improvements
- New features
- Documentation improvements
- Testing enhancements

## Pull Request Process

1. Ensure your PR addresses an existing issue or clearly describes the problem being solved
2. Update the README.md with details of changes if applicable
3. Add yourself to the contributors list if this is your first contribution
4. Ensure the PR passes all automated checks
5. Request review from maintainers

## Style Guide

### Writing Style
- Use clear, concise language
- Write for the target audience (students and professionals)
- Include practical examples
- Follow the existing content structure and formatting

### Technical Style
- Use appropriate code formatting
- Include relevant mathematical notation using KaTeX
- Add proper alt text for images
- Use consistent terminology

### Commit Messages
- Use the present tense ("Add feature" not "Added feature")
- Use the imperative mood ("Move cursor to..." not "Moves cursor to...")
- Limit the first line to 72 characters or less
- Reference issues and pull requests after the first line

## Questions

If you have any questions about contributing, feel free to open an issue with the "question" label.
