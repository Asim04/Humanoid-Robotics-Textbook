# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in this textbook project, please report it responsibly by contacting us directly rather than creating a public issue.

**Please do not report security vulnerabilities through public GitHub issues.**

To report a security issue, please email: [INSERT EMAIL ADDRESS]

When reporting a security vulnerability, please include:
- A clear description of the vulnerability
- Steps to reproduce the issue
- Potential impact of the vulnerability
- Any suggested fixes if known

### Response Timeline

We will acknowledge receipt of your vulnerability report within 48 hours, and we'll send a more detailed response within 1 week indicating the next steps in handling your report.

After the initial reply to your report, we will endeavor to keep you informed of the progress towards a fix and full announcement, and may ask for additional information or guidance.

### Disclosure Policy

When we receive a security bug report, we will assign it to a primary handler. This person will coordinate the fix and release process, involving the following steps:

1. Confirm the problem and determine the affected versions
2. Audit code to find any potential similar problems
3. Prepare fixes for all releases still under maintenance
4. Release fixes as quickly as possible

## Supported Versions

We release patches for security vulnerabilities. Which versions are eligible for receiving such patches depends on the severity of the vulnerability and the current development status of the textbook content.

| Version | Supported          |

| latest  | :white_check_mark: |

## Security Best Practices for Users

When working with this textbook and its examples:

1. Always use the latest version of all dependencies
2. Review code examples before running them in your environment
3. Use virtual environments to isolate textbook exercises
4. Follow security best practices when deploying robotic systems
5. Keep your development environment updated
